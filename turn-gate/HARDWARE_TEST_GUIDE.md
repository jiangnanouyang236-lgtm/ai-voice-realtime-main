# Turn Gate 真机测试清单

## 测试目标

第一轮不是追求 100% 正确，而是确认：完整表达能快速提交、自然停顿不会明显误截断、模型
失败时仍能安全收口。使用 `deploy/` 中的 Active 配置，建议安静环境和正常说话音量，每条
测试三次。

记录四项：是否被截断、从最后一个字到系统开始处理的主观等待、ASR 最终文本、Go/Python
日志中的 candidate 决策与耗时。

## A. 明确说完，应快速提交

| 编号 | 直接说的话 | 预期 |
|---|---|---|
| A1 | 帮我查一下今天青岛的天气。 | 约半秒提交，内容完整 |
| A2 | 给我讲一个简短的笑话。 | 约半秒提交 |
| A3 | 明天下午三点提醒我开会。 | 约半秒提交，时间信息完整 |
| A4 | 好的。 | 短回答也能正常提交 |

## B. 句中自然停顿，不应提前截断

停顿时不要发出声音，到指定时间后继续说完整句子。

| 编号 | 说法 | 预期 |
|---|---|---|
| B1 | 帮我查一下……（停 0.6 秒）……明天北京的天气。 | 不应在“查一下”后提交 |
| B2 | 我想去……（停 1.0 秒）……杭州西湖玩两天。 | 应继续听完 |
| B3 | 帮我设置一个提醒……（停 0.8 秒）……明天下午三点……（再停 0.8 秒）……提醒我开会。 | 两次停顿都不截断 |
| B4 | 我觉得这个事情……（停 1.3 秒）……还是应该先确认需求。 | 应继续听完 |

## C. 犹豫、修正与列举

| 编号 | 说法 | 预期 |
|---|---|---|
| C1 | 帮我查北京……不对……（停 0.6 秒）……上海的天气。 | 最终 ASR 应包含修正内容 |
| C2 | 我需要买苹果、牛奶……（停 0.8 秒）……还有面包。 | 不在“牛奶”后提交 |
| C3 | 嗯……（停 0.7 秒）……我想问一下怎么设置提醒。 | 不能只把“嗯”当成完整轮次 |
| C4 | 这个问题我想想……（停 1.4 秒）……我们先用第一种方案。 | 尽量继续听到后半句 |

## D. 边界与安全回退

| 编号 | 操作 | 预期 |
|---|---|---|
| D1 | 说“我想去”，停顿超过 1.8 秒 | 允许在 1600ms 左右保守收口，这是当前单工硬上限 |
| D2 | 说完一句后立刻在 0.4 秒内补一句 | 旧 candidate 不应截断新增语音 |
| D3 | 连续快速说两轮，每轮间隔约 1 秒 | 两轮 trace/utterance 不应串线 |
| D4 | 连续测试 20 轮 | 不应出现 candidate 队列持续增长或后续轮次越来越慢 |

## 通过建议

- A 组 12 次中至少 10 次正常快速提交。
- B/C 组 24 次中误截断不超过 2 次；发生时保存原句、停顿时长和完整日志。
- D2/D3 不允许出现旧 candidate 提交新语音或跨轮串线。
- Python 启动必须看到两个模型 `ready`，测试期间不能持续出现 `unavailable`。

如出现误截断，先不要改多个参数。保留该句连续复测三次，并记录 Smart、EOU probability、
candidate 总耗时和最终路径（early commit、continue、1000ms fallback 或 1600ms hard timeout）。
