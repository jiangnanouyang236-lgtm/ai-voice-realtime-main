# 音频硬件与前端矩阵

> 本文是生产讯飞语音硬件、自研 USB 音频硬件和 TCP 软件音频前端的边界真相源。
> 设备名、串口路径和现场配置仍以运行进程、脱敏配置输出及 `.ai/runtime.local.md` 为准。

## 当前结论

- 当前生产机器人使用“讯飞语音硬件模组”。模组在硬件内部完成 AEC、NS、AGC 等处理，
  并向操作系统提供默认麦克风和默认扬声器；Rust Client 不接入讯飞 SDK。
- Rust Client 使用系统默认音频设备即可。播放 TTS 时，默认麦克风仍持续输出经讯飞硬件
  处理后的音频，因此生产自然打断应优先基于这一路径实现。
- 当前生产 KWS 也由讯飞语音硬件模组完成。Rust Client 监听串口 JSON，将匹配的事件
  归一化为现有硬件唤醒事件；唤醒仍保持最高优先级和立即打断语义。
- `wzk-mic` / `wzk-speaker` 与本机 C++ `audio_frontend` 都是脱离讯飞的自研替代路线，
  当前尚未达到生产替换条件，不得用它们的本机配置推断生产机器人音频拓扑。
- 生产机器人和后续测试实体机使用相同类别的讯飞语音硬件与系统音频拓扑。

## 路线矩阵

| 路线 | 当前定位 | 音频入口/出口 | AEC / NS / AGC | KWS | 自然打断优先级 |
|---|---|---|---|---|---|
| 讯飞语音硬件模组 | 当前生产 | 操作系统默认麦克风与默认扬声器；Rust 走 CPAL/system，不使用 SDK | 硬件模组内部完成；播放期间持续提供处理后麦克风音频 | 硬件完成，Rust 监听串口 JSON | 第一阶段目标 |
| C++ `audio_frontend` TCP | 自研软件替代与开发测试 | 外部程序连接普通麦克风/扬声器，处理后通过 TCP 与 Rust 交换 PCM | 软件 WebRTC AEC，可组合软件 NS 等处理 | 可使用 C++ DS-CNN KWS TCP 事件 | 替代路线验证，不代表生产 |
| `wzk-mic` / `wzk-speaker` | 自研 USB 硬件替代实验 | ESP32-S3 作为系统 USB 麦克风/扬声器 | ESP-SR AEC 路线，仍未完成生产验收 | 当前固件不承担生产 KWS | 暂不作为生产功能首发目标 |

## Rust 音频格式事实

- Rust 内部音频固定为 PCM16、16kHz、mono、10ms 帧。
- CPAL 采集打开系统默认输入设备的默认原生配置；当原生采样率不是 16kHz或声道数不是
  mono 时，在 Rust 采集端下混并重采样为 16kHz mono。
- CPAL 播放选择系统默认输出设备，并请求 16kHz mono 输出流。当前 TTS PCM 源采样率也
  配置为 16kHz；若以后 TTS 源采样率变化，TTS processor 会重采样到内部采样率。
- 上述为代码和架构事实。实体机实际打开的设备、采样格式及全双工效果必须通过启动日志和
  硬件测试证据确认；配置或离线测试不能替代 `HARDWARE_VERIFIED`。

## 生产自然打断约束

- 第一阶段以讯飞生产路径为目标：TTS 下行继续播放时，Rust 从系统默认麦克风读取硬件
  处理后的音频并进行本地 VAD、候选缓存和 ASR Probe。
- 不为自然打断新增第二个 WebRTC PeerConnection 或音频通道；复用现有双向 WebRTC
  上行 RTP、下行 RTP和 control DataChannel，并用独立候选语义隔离 Probe 与正式轮次。
- Probe 不得进入对话历史，不得触发 LLM、MCP 或新 TTS；只有确认打断或新意图后，才取消
  当前播放并把候选音频提升为正常用户轮次。
- 普通 TTS 与唱歌播放使用相同的自然打断语义。唱歌继续复用当前 `round_id`、
  `playback_id`、interrupt 和迟到音频隔离；“别唱了，换一首”等新表达提升为正常轮次后，
  再由既有路由选择唱歌或其他能力。短提示音、确认音不单独开启自然打断候选窗口。
- 讯飞串口 KWS 始终高于 VAD/ASR Probe，必须保留当前立即打断路径。
- 第一阶段不依赖 TCP 软件 AEC，也不叠加硬件 AEC 与软件 AEC。替代路线以后独立验证。

## 仍需运行验证的事实

- 生产/测试实体机上 CPAL 实际选中的默认输入和输出设备名称。
- 默认设备实际打开的采样格式、16kHz mono 输出支持和播放期间连续采集行为。
- 讯飞硬件在真实 TTS 回声、双讲、距离和音量条件下的残余回声及自然打断边界。
- 当前部署二进制、环境配置和 Git commit 的确切绑定。
