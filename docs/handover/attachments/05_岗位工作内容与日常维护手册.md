## 五、现有服务启停

### 5.1 依赖顺序

启动顺序：数据库/模型 → 业务容器内 wrappers 与 MCP → Python Gateway/Admin → Go → 客户端。
停止按相反依赖顺序评估；共享模型或数据库停止前先确认其他会话与服务。
仅启动 `wzk_lam_avatar` 容器不代表其中 nohup 服务已自动恢复。
9月11日该容器无挂载且 `restart=no`；后续状态应重新查询。
现有容器可写层须纳入恢复资料，不能把删除重建容器当作普通重启。

以下示例仅操作 Go；其他服务先按服务清单确认准确容器名。

```bash
# 业务容器；先查当前 PID 并核对身份
pgrep -af gateway_server.py
```

## 六、配置、数据库与生效确认

1. 软件端口与模型连接参数：以启动环境及根 `.env` 为准，已有环境变量优先。
2. Bot/Robot/MCP/Agent/TTS Profile：以数据库及加载的 Runtime Snapshot 为准。
3. 保存配置后，Admin 执行 Apply / Reload，三个服务先校验后加载同一目标版本。
4. 分别检查 Gateway、LLM、TTS 的 `config_version`、`last_reload_error` 和实际请求。
5. 跨服务 Reload 不具备全局原子事务；部分失败应查各服务状态，再决定恢复步骤。

Admin 新代码默认监听业务容器 `0.0.0.0:8282`，宿主入口为 `10.10.6.121:15282`。
9月11日旧进程为 `18100`；新默认部署状态未验证，环境显式覆盖仍优先。
排查访问失败时先查实际监听及映射，不能仅凭源码默认断言服务已经迁移。

数据库维护先确认备份、目标库和迁移执行记录。
`scripts/init_config_db.py` 默认可能同步 legacy 配置和绑定，不能当只读检查运行。
已有库按实际未执行项核对 `scripts/migrations/`，不要盲目重复应用全部 SQL。
`config_snapshots` 只保留最近10份配置快照，不能替代完整数据库或文件备份。
配置保存、快照加载与真实业务生效是三个不同检查点。

## 七、故障排查顺序

先固定时间、Robot、session、trace，再沿真实链路定位；不要用旧日志推断当前故障。

| 顺序 / 现象 | 优先检查 | 判断边界 |
|---|---|---|
| 1. 客户端不在线 | 用户服务、当前进程配置、网络与注册身份 | SSH 超时不等于语音进程宕机 |
| 2. WS 通、ICE 不通 | 下发 ICE、候选对、UDP、FRP/TURN | 信令通不等于媒体通 |
| 3. 有连接无输入 | 软件采音日志、串口事件、设备权限 | 硬件问题转硬件人员协查 |
| 4. 无识别文本 | Gateway 音频提交、STT 排队和 ASR 模型 | STT stream 是收齐后识别 |
| 5. 无回答/工具失败 | LLM、Bot绑定、MCP连接及上游模型 | MQTT 发出不等于动作完成 |
| 6. 有文本无声音 | TTS Profile、参考音频、PCM、播放日志 | 下行轨道打开不等于播放完成 |
| 7. Vision/角度异常 | 配置子目录、文件更新时间、本机5200 | 图片/本机配套服务归硬件人员 |
| 8. 重启后仍旧配置 | ExecStart、脚本覆盖、当前PID目标变量 | 文件改动不等于进程已加载 |

网络拓扑按9月14日资料：新中转服务器 NGINX 15011 → 回环15010 → FRP → Base Go15010。
RTP 媒体由 ICE 决定直连或 TURN，不能将 FRP 信令映射视为音频中继。
新入口只转发 `/ws`；在该入口请求 `/internal/status` 返回404不能认定 Go 宕机。
网络中转检查按《WebRTC 网络迁移与机器人运维交接》执行，地址由接管资料提供。
